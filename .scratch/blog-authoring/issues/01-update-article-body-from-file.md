# 01: 通过文件更新文章正文

**What to build:** 博客作者和本地产品可以通过安装后的 `yoho blog update <id> --body-file` 替换文章正文，也可以同时修改标题。未指定的内容保持原样，整次更新沿用文章版本、并发保护和结果协议。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Spec:** [第二个里程碑规格](../spec.md)。

- [ ] 先完成本任务所需的更新模型调整，区分未提供正文、明确提供空正文和实际内容变化；保留原有标题更新行为，不引入未使用的兼容接口。
- [ ] 安装后的 CLI 接受 `--body-file`；仅提供正文也可更新。标题变为可选，但至少提供一项内容变更参数，单独提供版本、项目或输出参数时返回 `INVALID_ARGUMENT`，退出码为 2。
- [ ] 正文输入路径相对于调用进程的当前目录解析，与 `--project` 无关；输入可在项目之外，输入文件保持不变。输入与目标文章是同一实际文件时返回 `INVALID_ARGUMENT`，保留原文。
- [ ] 输入必须是可读取的普通 UTF-8 文本文件。允许空正文，逐字保留空白、换行、结尾、MDX 文本和图片引用；不提取输入文件中的 frontmatter，不渲染、不转换路径，不为 `-` 增加 stdin 语义。
- [ ] 只更新正文时，包含 BOM、分隔符、注释和原始换行的 frontmatter 整段保持原样。仅更新标题时正文保持原样；同时更新标题与正文时作为一次操作提交。
- [ ] 任一参数无效、正文读取失败或目标文章无效时，整个请求失败。非法 UTF-8 输入属于参数错误，权限和文件读取错误沿用既有分类；不得先修改标题再报告正文错误。
- [ ] `--if-match` 适用于正文及标题组合更新；过期版本即使请求内容相同也返回 `ARTICLE_CONFLICT`，退出码为 3。未提供版本时，只基于当前文章修改指定内容。
- [ ] 相同正文与规范化后相同标题不触发写入，返回 `changed=false`，文件内容、修改时间和文章版本不变。成功结果继续包含 `id`、`title`、`revision` 与 `changed`，随后查看的版本一致。
- [ ] 保留文章标识、文件名、扩展名、权限和未指定元数据，不自动修改日期或文章状态。沿用已有路径边界、目标隔离和 Markdown、MDX 歧义处理。
- [ ] 更新使用既有锁和完整内容原子替换。提交前检测到内容变化时报告冲突；提交前取消、权限错误或 I/O 错误保留原文章，正常失败清理暂存文件并释放锁。
- [ ] 通过安装后的 CLI 子进程，在临时博客中验证相对输入路径、显式项目、空正文、正文与标题组合、无变化、输入失败、同文件拒绝、版本冲突、并发条件更新及取消。使用实际文件比较证明内容保护，回归首个里程碑验收。
- [ ] 用博客实际内容加载器验证临时文章更新后仍可读取。文本明确区分修改和未修改；JSON 成功与失败均独立写入 stdout，stderr 只承载诊断，完整参数调用无需交互，并更新正文编辑使用说明。
