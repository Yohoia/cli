# 02: 更新描述与标签

**What to build:** 博客作者和本地产品可以修改描述、替换或清空标签，并将标题、正文、描述与标签放在一次更新中提交。任一输入或字段编辑失败时，原文章完整保留。

**Blocked by:** 01: 通过文件更新文章正文。

**Status:** resolved

**Spec:** [第二个里程碑规格](../spec.md)。

- [x] 安装后的 `update` 接受 `--description`、可重复的 `--tag` 与 `--clear-tags`，与已有标题、正文和版本参数共同使用。至少提供一项内容变更参数的规则继续有效。
- [x] 描述按字符串保存，允许显式空字符串，不自动修剪空白。未提供描述时保留其原始值和源文本。
- [x] 每个 `--tag` 提供一个标签，不按逗号切分；去除首尾空白，拒绝空白标签，按首次出现顺序去重，比较区分大小写。
- [x] 提供标签时替换整组标签，不与旧值合并。`--clear-tags` 明确设为空列表，并与 `--tag` 互斥；都未提供时保留原标签。
- [x] 支持仅更新描述、仅更新标签，以及标题、正文、描述与标签的组合更新。全部字段在一次受锁保护的操作中校验和提交，不留下部分更新。
- [x] 相同描述或相同有序标签列表不触发无关写入；默认空标签与清空空标签也不为补齐默认值写文件。完整请求无变化时，文章版本与修改时间不变。
- [x] 仅调整指定字段及必要 YAML 语法，保留字段外的注释、排版、未知元数据、日期、正文和图片引用，不顺带回写其他默认字段。继续支持既有独立别名、继承字段与块标量编辑。
- [x] 若 YAML 锚点、别名或合并使未指定字段发生语义变化，返回 `ARTICLE_INVALID` 并保留整篇原文。继续沿用 `gray-matter` 的语义解释，拒绝无法完整表示为 JSON 的文章元数据。
- [x] 描述和标签更新沿用 `--if-match`、同版本并发更新、目标隔离、原子替换、文件权限、错误清理和取消规则，不自动改变文章状态或日期。
- [x] 通过安装后的 CLI 子进程验证空描述、标签规范化、逗号作为标签内容、大小写、顺序、整组替换、清空、互斥参数、多字段成功及整体失败。版本冲突和无变化测试观察实际文章与输出。
- [x] 在临时文章上验证 BOM、CRLF、注释、未知字段及 YAML 关联字段的保留行为，并用博客实际内容加载器验证描述、标签和正文兼容性。回归现有 CLI 验收。
- [x] 保留既有更新结果字段、JSON 通道与退出码，完整调用无需交互，更新描述与标签的使用说明；不加入任意元数据键或日期编辑入口。

## Answer

- 已实现描述原样替换、显式空描述、规范化有序标签替换与清空，并支持与标题、正文及文章版本合并为一次原子更新。
- YAML 编辑沿用源区间补丁，保留未指定文本，新增序列字段支持；解析后核对完整预期元数据，拒绝锚点等关联修改。
- 红灯证据：安装后的真实 CLI 分别对 `--description` 与 `--tag` 返回 `INVALID_ARGUMENT`（未知选项），新增描述与标签验收各自失败；实现后转绿。
- 新增 9 项安装后 CLI 验收，覆盖空描述、标签规范化/顺序/逗号/大小写、无变化、BOM/CRLF/注释/继承/别名/块标量、多字段整体成功与失败、版本冲突、并发和博客实际加载器兼容性。全部写入临时文章，真实博客仅作为读取器使用。
- 验证：`pnpm check`、`pnpm format:check`、`git diff --check` 通过；显式指定真实博客项目的 `pnpm test` 共 49 项通过（含既有安装后 CLI 回归）。
