# 04: 管理文章状态

**What to build:** 博客作者可以通过 `yoho blog update <id> --status` 在草稿、已发布和已归档之间转换文章。CLI 同时处理博客的 `draft` 标记，使本地文章在下一次被博客读取时符合预期展示规则。

**Blocked by:** 01: 通过文件更新文章正文。

**Status:** resolved

**Spec:** [第二个里程碑规格](../spec.md)。

- [x] 安装后的 `update` 接受 `--status`，只允许 `draft`、`published`、`archived`，支持三种状态之间的所有显式转换。仅提供状态也构成有效内容更新。
- [x] 草稿写入 `status=draft` 与 `draft=true`；已发布写入 `status=published` 与 `draft=false`；已归档写入 `status=archived` 与 `draft=true`。两个字段作为一次变更处理。
- [x] 当前状态相同但 `draft` 与目标不一致时仍需更新。按既有读取默认值解释后两个字段已满足目标组合时，不为补齐显式默认值写入，返回 `changed=false` 并保留文章版本与修改时间。
- [x] 可与其他已支持的更新字段一次提交，保留整体成功或整体失败的规则。未提供 `--status` 时，标题、正文及其他编辑不改变原始状态或草稿标记。
- [x] 不自动修改发布日期、更新时间、其他元数据、正文、标识、扩展名或权限。状态字段涉及 YAML 关联、无法独立修改时，明确失败且原文不变。
- [x] 状态更新沿用 `--if-match`。过期版本，包括无变化请求，返回 `ARTICLE_CONFLICT`；无条件更新基于当前文章，两个基于同一旧版本的变更最多一个提交成功。
- [x] 管理列表继续包含所有状态，筛选与排序保持不变。文章设为已发布仅改变本地数据，不执行 Git 操作、同步、构建、部署或定时发布。
- [x] 用安装后的 CLI 覆盖所有状态转换、缺失 `draft`、显式草稿标记、同状态纠正、无需写入、组合更新、非法状态、版本冲突与并发，观察输出及实际文件。
- [x] 使用博客实际内容加载器验证草稿不公开、已发布可读、归档不公开、恢复后重新符合展示条件，并核对日期与原始图片引用保持不变。测试使用临时文章，不依赖创建命令才能建立样本。
- [x] 文本和 JSON 结果沿用更新契约，保留错误通道、退出码与非交互行为，回归已支持的业务命令，并在使用说明中区分文章状态与线上部署结果。
