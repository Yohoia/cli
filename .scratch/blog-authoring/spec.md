# Yoho CLI 第二个里程碑：本地博客文章创作与管理

Status: ready-for-agent

## Problem Statement

博客作者目前可以列出文章、查看完整内容和修改标题，但新建草稿、编辑正文与元数据、调整文章状态和删除文章仍需手动操作。终端用户与本地产品无法通过同一套 CLI 完成文章从草稿到归档的管理流程。

扩展编辑范围后，CLI 仍需保留未指定修改的内容，并继续兼容既有博客。文章状态与网站可见性由不同字段共同决定，单独修改状态可能无法让文章按预期展示。删除操作还需要明确目标、预览结果和显式执行授权。

## Solution

在既有 `yoho blog` 命令组中增加新建草稿与删除文章的能力，并扩展 `update`，支持修改正文、描述、标签和文章状态。保留已有文章标识、项目定位、版本检查、文本与 JSON 输出契约。

新文章默认是草稿。正文通过 UTF-8 文件输入。一次更新可以修改多个字段，并作为一次文章写入提交。状态更新同时处理博客的 `draft` 字段，使草稿、已发布和已归档文章符合站点既有展示规则。删除提供只读预览，实际删除要求显式参数。

本里程碑仍管理本地文章。修改为已发布状态后，文章在博客下一次读取本地内容时符合公开展示条件；CLI 不执行同步、Git 推送或网站部署。

## User Stories

1. 作为博客作者，我希望安装后的 `yoho` 提供新建文章命令，以便从终端开始写作。
2. 作为博客作者，我希望明确指定文章标识，以便控制文件位置与访问地址。
3. 作为博客作者，我希望新建子目录中的文章，以便沿用现有文章组织方式。
4. 作为博客作者，我希望新文章默认为草稿，以便避免意外进入公开展示范围。
5. 作为博客作者，我希望新建时填写标题、描述与发布日期，以便生成符合博客契约的文章。
6. 作为博客作者，我希望选择 Markdown 或 MDX，以便使用博客已支持的格式。
7. 作为博客作者，我希望省略正文时生成空正文草稿，以便先记录文章计划。
8. 作为博客作者，我希望通过文件提供正文，以便保留多行内容与图片引用。
9. 作为博客作者，我希望新建时指定标签，以便对文章分类。
10. 作为博客作者，我希望相同文章标识不能被重复创建，以便保留已有文章。
11. 作为博客作者，我希望 Markdown 与 MDX 共享文章标识的唯一性约束，以便避免产生歧义。
12. 作为博客作者，我希望重复执行创建请求不会覆盖已有文章，以便安全处理重试。
13. 作为本地产品的调用方，我希望创建结果包含完整文章与文章版本，以便继续查看或编辑。
14. 作为博客作者，我希望按文章标识修改正文，以便完成实际写作。
15. 作为博客作者，我希望正文文件的空白与换行保持原样，以便保留 Markdown 和 MDX 排版。
16. 作为博客作者，我希望通过空正文文件清空正文，以便明确替换已有内容。
17. 作为博客作者，我希望输入文件读取失败时目标文章不变，以便继续使用原文。
18. 作为博客作者，我希望输入文件必须是有效 UTF-8 文本，以便避免静默损坏内容。
19. 作为博客作者，我希望修改描述，以便更新文章摘要。
20. 作为博客作者，我希望明确替换整组标签，以便准确控制分类结果。
21. 作为博客作者，我希望明确清空标签，以便移除旧分类。
22. 作为博客作者，我希望标签中的首尾空白和重复值有统一处理规则，以便获得稳定结果。
23. 作为博客作者，我希望一次更新同时修改标题、正文、描述和标签，以便避免多次写入。
24. 作为博客作者，我希望其中任一输入无效时整次更新都不生效，以便避免只完成部分修改。
25. 作为博客作者，我希望只修改正文时保留原有 frontmatter，以便保留注释与元数据排版。
26. 作为博客作者，我希望只修改元数据时保留正文，以便避免误改文章内容。
27. 作为博客作者，我希望未指定的字段、作者、日期与图片引用保持原样，以便保护已有信息。
28. 作为博客作者，我希望更新不改变文章标识、文件名与扩展名，以便保留已有链接。
29. 作为博客作者，我希望相同内容的更新不重写文章，以便避免无意义的变更。
30. 作为博客作者，我希望可以把文章设为草稿，以便退出公开展示范围继续编辑。
31. 作为博客作者，我希望可以把文章设为已发布，以便博客按现有规则读取文章。
32. 作为博客作者，我希望可以归档文章而保留原文，以便停止展示但不删除内容。
33. 作为博客作者，我希望可以将归档文章恢复为草稿或已发布，以便重新使用已有内容。
34. 作为博客作者，我希望状态调整同时处理 `draft` 字段，以便避免状态显示为已发布但网站仍隐藏文章。
35. 作为博客作者，我希望仅编辑标题或正文时不改变文章状态，以便避免意外公开草稿。
36. 作为博客作者，我希望状态更新不自动修改发布日期或更新时间，以便保留既有日期记录。
37. 作为本地产品的调用方，我希望所有字段更新都支持文章版本检查，以便避免覆盖较新的内容。
38. 作为本地产品的调用方，我希望过期版本即使请求的是相同内容也被拒绝，以便识别失效的编辑依据。
39. 作为博客作者，我希望不提供版本时基于当前文章更新指定字段，以便直接完成终端编辑。
40. 作为博客作者，我希望并发的条件更新最多只有一个成功，以便避免相互覆盖。
41. 作为博客作者，我希望删除前预览文章标识、位置与版本，以便核对目标。
42. 作为博客作者，我希望预览不修改任何文章，以便放心检查删除请求。
43. 作为博客作者，我希望实际删除要求显式授权，以便降低误操作的机会。
44. 作为本地产品的调用方，我希望删除也支持文章版本检查，以便避免删除已被他人修改的内容。
45. 作为博客作者，我希望删除只移除目标文章，以便保留图片、其他文章与所在目录。
46. 作为博客作者，我希望不存在或存在歧义的目标明确报错，以便修正文章标识。
47. 作为博客作者，我希望创建与删除拒绝通过符号链接操作目标，以便准确知道实际创建或删除的位置。
48. 作为博客作者，我希望文章操作不能越出内容目录，以便限定操作范围。
49. 作为博客作者，我希望其他文章损坏不影响当前目标的创建、更新或删除，以便独立处理单篇文章。
50. 作为博客作者，我希望写入失败或提交前取消时原有文章完好，以便继续工作。
51. 作为本地产品的调用方，我希望完整参数调用始终无需交互，以便可靠执行自动化任务。
52. 作为本地产品的调用方，我希望新命令沿用 JSON 结果、错误码与退出码，以便复用现有调用逻辑。
53. 作为终端用户，我希望文本结果明确区分创建、修改、未修改、删除预览和实际删除，以便理解操作结果。
54. 作为博客作者，我希望修改后的文章能被博客实际内容加载器读取，以便确认编辑结果有效。
55. 作为博客作者，我希望新功能通过已安装的 CLI 验收，以便确认交付物可用。
56. 作为博客作者，我希望所有写入验收使用临时副本，以便保护真实文章。
57. 作为现有调用方，我希望原有列表、查看和标题更新保持兼容，以便继续使用已有脚本。

## Implementation Decisions

### 既有架构与模块职责

- 保持 TypeScript、Node.js 24、pnpm、Commander、Zod 与单包分层结构。
- 命令适配器解析参数和正文输入文件。文章服务处理创建、字段更新、状态联动、删除授权和文章版本规则。文件适配器处理文章定位、内容解析、锁及文件提交。输出适配器沿用统一结果协议。
- 将当前只表达标题变化的更新模型扩展为明确的字段变更。未提供字段与明确提供空值必须可区分。内部类型由边界校验得到，业务逻辑不处理未校验的参数对象。
- 继续用 `gray-matter` 解释元数据语义，用源片段定位支持局部修改。沿用现有博客内容契约和 JSON 输出 ADR，不引入第二套文章格式。

### 命令与项目定位

- 新增 `yoho blog create <id>` 和 `yoho blog delete <id>`，扩展既有 `yoho blog update <id>`。
- 所有业务命令沿用 `--project` 与 `--json`。从运行目录向上定位项目的行为保持不变。创建只在已识别的博客项目内进行，不初始化新的博客项目。
- 文章标识继续由相对于文章目录的路径去掉 Markdown 或 MDX 扩展名得到，支持子目录，不从标题推导或重命名文章标识。
- 完整参数调用无需终端输入。不增加交互编辑器、确认提示或全局项目绑定。

### 创建草稿

- `create` 必须提供 `--title`、`--description` 和 `--published-at`。标题沿用现有去除首尾空白、非空单行文本规则。描述是字符串，允许显式空字符串，不自动去除空白。
- `--published-at` 接受有效的 ISO 日期或带时区的 ISO 时间。仅日期表示 UTC 当日零点，时间转换为对应 UTC 时间。拒绝不存在的日期、无时区的时间及解析后自动滚动到其他日期的输入。
- `--format` 接受 `md` 或 `mdx`，默认 `md`，只决定新文章扩展名。`--body-file` 可选，未提供时正文为空。可重复的 `--tag` 指定标签，省略时为空列表。
- 新文章写入明确的标题、描述、发布日期、`status=draft`、`draft=true`、`language=zh` 和标签。`publishedAt` 写为可被既有博客读取的 UTC ISO 字符串，不自动写入 `updatedAt`。
- 新建时不能指定已发布或已归档状态，需通过后续更新显式改变状态。新建元数据使用合法 YAML，正文原样接在 frontmatter 结束分隔符之后，不额外修剪或补充正文换行。
- 子目录不存在时可在内容目录内创建。相同文章标识的任一扩展名已存在时返回 `ARTICLE_ALREADY_EXISTS`，退出码为 3，不覆盖原内容。已有两个候选文章时继续报告 `ARTICLE_ID_AMBIGUOUS`。
- 存在但损坏的文章仍占用其文章标识。创建不能利用格式错误、另一扩展名或重复请求绕过防覆盖规则。目录或其他非普通文件占据目标位置时明确失败。
- 成功返回与 `show` 相同形状的完整文章，包含 `id`、`path`、`metadata`、`content` 和 `revision`，且随后 `show` 返回同一文章版本。

### 正文输入与标签

- `--body-file` 在 `create` 与 `update` 中含义一致。相对输入路径以调用进程的当前目录为基准，与 `--project` 无关。输入文件可以位于博客项目之外，但本命令不修改输入文件本身。
- 正文输入文件与目标文章解析为同一实际文件时，返回 `INVALID_ARGUMENT`，不执行更新，避免将包含原 frontmatter 的整篇文章误作正文并覆盖输入文件。
- 输入必须是可读取的普通 UTF-8 文本文件。允许空正文文件，不进行 Markdown 渲染、frontmatter 提取、图片路径转换、换行转换、空白修剪或结尾补行。文件中的全部文本作为正文输入。
- `--body-file -` 不具有标准输入的特殊含义。本里程碑不增加 stdin 输入。所有输入文本先读取、校验，随后才提交文章变化。
- `--tag` 每出现一次提供一个标签，不按逗号切分。标签去除首尾空白，拒绝空白标签，按首次出现的顺序去重，比较区分大小写。
- 更新时提供的标签替换整组标签，不与旧标签合并。`--clear-tags` 将标签设为空列表；它与 `--tag` 互斥。两者都未提供时保留原标签。

### 多字段更新与内容保护

- `update` 接受可选的 `--title`、`--description`、`--body-file`、可重复的 `--tag`、`--clear-tags` 和 `--status`。至少提供一项内容变更参数，单独提供版本或输出参数属于参数错误。
- 既有 `update --title` 用法继续有效。不增加任意元数据键写入、直接编辑原始 frontmatter 或修改日期的入口。
- 一次请求的所有字段作为一次更新处理。任一参数无效、输入无法读取、文章无效或无法独立修改指定字段时，整次操作失败，不留下部分字段更新。
- 未提供的元数据字段保留其原始源文本。未指定正文时，正文逐字节保留。只修改正文时，包含 BOM、分隔符和换行的原始 frontmatter 整段保留。
- 修改指定元数据时允许调整这些字段的值与必要语法。保留字段外的注释、排版、未知字段及图片引用。字段不存在时仅插入本次指定字段，状态联动字段除外，不顺带回写其他读取默认值。
- YAML 锚点、别名或合并字段不能使未指定字段发生语义变化。若无法完成独立编辑，返回 `ARTICLE_INVALID`，保留原文。支持现有标题编辑已覆盖的独立别名、继承字段和块标量场景。
- 元数据使用解析后的值判断是否变化，正文按完整文本判断。标签按规范化后的有序列表判断。整个请求没有实际变化时返回 `changed=false`，不写文件、不改变文章版本或文件修改时间。
- 未提供 `--status` 时保留原始 `status` 与 `draft`。无论编辑哪些字段，都不自动修改 `publishedAt`、`updatedAt`、文章标识、扩展名或文件权限。
- 更新结果继续包含 `id`、`title`、`revision` 与 `changed`，不移除或改名既有字段。调用方通过 `show` 读取更新后的完整文章。

### 文章状态与网站展示

- `--status` 只接受 `draft`、`published`、`archived`，三种状态之间均可显式转换。
- 设置草稿时写入 `status=draft` 和 `draft=true`。设置已发布时写入 `status=published` 和 `draft=false`。设置已归档时写入 `status=archived` 和 `draft=true`。
- 状态更新将两个字段视为同一次变更。文章当前 `status` 相同但 `draft` 不符合目标组合时仍需修改。两个字段语义上已符合目标组合时，不为补齐显式默认值而写文件。
- 已发布状态表示文章满足博客本地内容读取器的公开筛选条件，不表示 CLI 已将文章部署到线上。发布日期仍用于既有排序，不增加定时发布规则。
- 管理列表继续包含全部状态，沿用现有 `--status` 筛选、发布日期倒序和同日文章标识排序。不增加列表默认公开过滤，也不将文章状态等同于线上网站状态。

### 删除预览与实际删除

- `delete` 接受 `--dry-run`、`--yes` 和可选的 `--if-match`。只读预览不要求 `--yes`。没有 `--dry-run` 的实际删除必须提供 `--yes`，否则返回 `INVALID_ARGUMENT`，退出码为 2，且不等待输入。
- 同时提供 `--dry-run` 与 `--yes` 时，只执行预览。`--yes` 不绕过路径、文章数据、歧义或文章版本检查。
- 预览与实际删除都定位并读取目标文章。预览返回 `id`、`path`、`revision`、`dryRun=true` 与 `deleted=false`，不创建文章目录、锁文件或其他持久文件。
- 实际删除只移除目标文章，不删除其图片、附件、其他文章或父目录。成功返回 `id`、`path`、被删除文章的 `revision`、`dryRun=false` 与 `deleted=true`。
- 删除后 `show` 返回 `ARTICLE_NOT_FOUND`，列表中不再包含该文章。重复删除仍返回 `ARTICLE_NOT_FOUND`，退出码为 3，不把不存在的目标报告为成功删除。
- 目标文章损坏、目标不唯一或定位失败时不执行删除。此命令不提供强制删除损坏文章的入口。其他文章损坏不影响有效目标的删除。
- 删除预览不预留目标，也不保证之后内容未变。调用方若要求实际删除的是预览时的文章，必须将预览得到的版本传给实际删除的 `--if-match`。

### 文章版本、并发与文件提交

- 所有字段更新沿用可选的 `--if-match`。提供版本时，在同一受锁保护的操作中检查版本与提交变更。过期版本返回 `ARTICLE_CONFLICT`，退出码为 3，包括无实际变化的更新请求。
- 删除预览与实际删除也验证传入的 `--if-match`。实际删除在持有锁时读取当前文章并检查版本。未指定版本的更新与删除基于当前文章执行。
- 创建、更新和实际删除对相同文章标识共享互斥规则，包含文章尚不存在和 Markdown、MDX 两种扩展名竞争的情况。实现需使新操作与原有标题更新遵守同一规则。
- 两个并发创建请求至多一个创建成功。两个基于相同旧版本、各自会改变内容的更新请求至多一个成功。携带相同文章版本的更新与删除竞争时，不能两个都基于该旧版本成功提交。
- 创建不能覆盖并发产生的文章。更新使用完整暂存内容与原子替换，不让读取者看到半篇文章。实际删除在提交时移除整个目标文章，不先清空正文。
- 写入或删除前重新检查路径、当前内容与锁的有效性。能检测到的外部文件变化报告冲突。锁协调 CLI 进程，不声称能阻止未遵守锁协议的外部编辑器在最终检查后写入。
- 提交前的参数错误、文章错误、读写错误或取消保持原有文章完好，不留下半成品或暂存文章。创建失败不留下新文章，允许保留已创建的空父目录。提交完成后不因清理失败回滚已经完成的文章操作。
- 锁和暂存文件不会作为文章参与解析或显示。操作结束时释放本次锁，正常失败时清理暂存文件；沿用现有取消、锁超时与过期锁处理行为。

### 路径与数据边界

- 保留现有文章标识校验、内容目录边界和 Markdown、MDX 歧义规则。创建校验已存在的父目录与最终候选目标，不因目标尚不存在而跳过目录边界检查。
- 创建与删除拒绝逻辑目标或内容目录以内的父目录含有符号链接的路径。越界路径返回现有 `PATH_OUTSIDE_CONTENT`；指向目录内的链接返回 `ARTICLE_INVALID`。不自动删除链接或跟随链接修改另一篇文章。项目根目录解析沿用既有行为。
- 查看与更新已支持的目录内链接行为继续受原有边界约束。目标链接的并发编辑仍须遵守现有锁保护，不扩展可访问范围。
- 不扫描或校验与目标无关的文章以决定创建、更新或删除。列表继续在遇到损坏文章时明确失败，不返回静默缺失的列表。
- 创建和更新后的文章必须满足博客现有元数据契约。保留未知元数据的语义及既有 YAML 标量解释。继续明确拒绝无法完整表示为 JSON 的元数据。

### 输出、错误与交付

- 默认文本输出明确显示目标与操作结果，删除预览必须标明尚未删除。JSON 成功沿用包含 `ok=true` 和 `data` 的结果，失败沿用包含 `ok=false`、`error.code` 和 `error.message` 的结果。
- 成功与失败的 JSON 均单独写入 stdout，stderr 只承载诊断。完整参数请求不混入确认提示或进度信息。
- 保留既有错误码，新增 `ARTICLE_ALREADY_EXISTS` 表示新建目标已占用。正文不是有效 UTF-8、标签参数矛盾、日期输入无效或缺少删除授权均为参数错误。有效输入路径的权限错误与文件读取错误沿用权限和 I/O 分类。
- 退出码继续为成功 0、参数或路径边界错误 2、文章数据错误或版本冲突 3、权限错误 4、文件读写错误 5、用户取消 130。
- 通过本地 npm 安装包交付，在 macOS 与 Node.js 24 上验收。更新使用说明中的新命令、参数、状态语义与删除行为，不改变现有安装和调用入口。

## Testing Decisions

### 测试边界与既有依据

- 继续使用首个里程碑已由用户确认的测试边界，以本地打包并安装后的真实 CLI 子进程为主。提供参数、运行目录与临时博客，观察 stdout、stderr、退出码以及实际文章内容。
- 该边界一次覆盖命令参数、文章服务、文件适配器、内容修改、文章锁和输出协议。复用现有安装、样本生成、子进程启动与清理支持，不为各内部方法另建重复测试。
- 博客实际内容加载器仍是兼容性依据，沿用当前临时文章加载测试的方式，显式使用本地内容模式。它补充验证状态筛选、元数据与图片展示转换，不替代 CLI 的源文件保留检查。
- 好的测试断言使用者可观察的行为。并发测试使用独立 CLI 进程，错误与取消测试检查原始文件结果，不断言模块名称或内部调用顺序。
- 所有创建、更新和删除发生在临时博客或临时副本。真实文章只允许只读检查。目标之外的文件使用前后内容比较证明未变。

### 必须覆盖的外部行为

1. 从最终安装位置运行 `create`、扩展后的 `update`、`delete`，并回归现有 `list`、`show` 与标题更新。
2. 在博客根目录与子目录自动定位项目，从其他目录显式指定项目，并验证无项目时不会创建文章。
3. 创建普通与子目录草稿，覆盖 Markdown、MDX、空正文、正文文件、中文标题、引号、必需元数据及稳定的完整文章结果。
4. 使用相对正文路径和显式项目参数，确认正文路径相对于调用目录。验证正文空白、图片引用、换行与 MDX 文本保持原样。
5. 验证同扩展名、另一扩展名、已损坏文章、目标目录和重复创建均不会覆盖已有内容。并发不同扩展名创建相同文章标识时至多一个成功。
6. 验证缺少参数、非法标题、未知格式、空白标签、无效日期、无时区时间和不存在日期均明确失败。验证日期与带偏移时间的 UTC 含义。
7. 分别更新正文、描述与标签，覆盖空描述、空正文、替换标签、清空标签、标签去重与顺序，以及互斥标签参数。
8. 同时更新多个字段并读回。任一参数无效、正文读取失败或指定字段无法独立编辑时，全部字段及文章版本保持不变。
9. 对 BOM、CRLF、注释、未知元数据、日期、图片引用、块标量、别名和合并字段进行内容保护回归。元数据更新保留正文，正文更新保留整个 frontmatter。
10. 验证所有未指定字段、文章标识、扩展名与文件权限保持不变，读取默认值不会无故回写。
11. 验证规范化后相同的元数据、相同正文与完整无变化请求返回 `changed=false`，文件内容、修改时间和文章版本均不变。
12. 覆盖三种状态的互相转换，缺少 `draft`、显式 `draft=true` 与状态不一致的组合，以及同状态但需要修改 `draft` 的情况。
13. 通过博客实际内容加载器验证新建草稿不公开、设为已发布后可读、转回草稿或归档后不公开，且未修改原始日期。
14. 使用当前版本成功更新，使用旧版本更新任一字段或提交无变化请求均失败。未提供版本时只修改当前文章的指定字段。
15. 两个独立 CLI 进程持相同旧版本提交不同更新，验证仅一个成功、另一个冲突，文章始终完整。
16. 删除预览覆盖文本与 JSON，不要求授权、不修改任何内容、不留下锁或暂存文件，并正确返回目标与文章版本。
17. 实际删除缺少 `--yes` 时非交互失败。同时提供预览与授权时仍只预览。授权参数不能绕过过期版本或目标校验。
18. 按当前版本实际删除后，目标消失、其他文章和图片不变、父目录保留，`show` 与重复删除报告不存在，正常列表不再包含目标。
19. 预览后改变文章，用旧版本删除时保留新内容。测试更新与删除持相同旧版本竞争，验证不会同时提交成功。删除与创建对同一文章标识的结果不出现部分内容或双扩展名歧义。
20. 覆盖不存在、损坏、歧义、路径越界、符号链接与父目录链接的目标。其他文章损坏时，有效目标仍可创建、更新或删除。
21. 正文文件不存在、为目录、无读取权限或含非法 UTF-8 时明确失败，原有文章保持不变。创建与更新不修改正文输入文件。
22. 在创建提交、更新替换和删除提交前触发权限错误、I/O 错误或取消，检查原有文章、无半成品和暂存清理。覆盖锁竞争及取消释放行为。
23. 检查每类新操作的成功与失败 JSON 都可单独从 stdout 解析，stderr 不污染结果，错误码与退出码符合契约，文本明确区分预览和实际操作。
24. 运行首个里程碑累计验收及本里程碑新增验收，从最终本地安装包完成草稿创建、编辑、状态转换、删除预览与删除的临时博客完整流程。

上述行为全部通过后，本里程碑才算完成。

## Out of Scope

- PageHush 同步、后台 API、远程文章管理、网站构建与部署。
- 自动 Git 提交、推送、分支操作或触发站点发布。
- 修改既有文章的发布日期、更新时间、语言、封面或任意未知元数据字段。
- 重命名或移动文章、批量操作、图片上传、附件删除、链接修复和全文搜索。
- 定时发布、文章审核、发布队列和单独的发布服务。
- 删除回收站、备份、撤销与恢复、强制删除损坏文章。删除授权允许移除目标本地文章，CLI 不承诺可恢复。
- 从 stdin 输入正文、交互编辑器、TUI、Web 控制台和文章模板体系。
- Skill 安装与分发、AI 对话、模型调用、Tool Registry、MCP Server 和第三方插件体系。
- 全局项目绑定、公开 npm 发布、单文件二进制分发、Linux 与 Windows 安装验收。

## Further Notes

- 本规格承接对话中提出的第二个博客管理里程碑。命令参数、状态联动、日期输入和删除授权细节是本次依据既有契约作出的设计选择，不表示这些细节已逐条获得用户确认。
- 测试沿用首个里程碑中用户已确认的安装后 CLI 边界与博客实际内容加载器，不增加新的测试边界。
- 首个里程碑规格仍保留为历史验收依据。本规格只扩展其明确纳入本次的文章创作与管理能力，原有输出、内容保护和版本契约继续有效。
- 当前 `ready-for-agent` 表示规格已具备拆分和实现条件，不表示新功能已经实现。后续任务使用本功能独立目录，不重新打开已完成的首个里程碑任务。
