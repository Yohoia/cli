# 01: 安装 CLI 并列出文章

**What to build:** 用户安装本地 npm 包后，可以在 macOS 上通过 `yoho blog list` 查找现有博客的全部文章。命令支持项目定位、状态筛选、稳定排序，以及面向终端和本地产品的两种输出。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Spec coverage:** 用户故事 1–10、30、35–42、44。本功能规格、术语表和已有 ADR 是行为依据。

- [ ] 使用已确认的 TypeScript、Node.js、pnpm、Commander、Zod 和单包结构，构建可本地安装的 npm 包；安装后实际运行 `yoho blog list`，不以直接运行开发源代码代替交付验收。
- [ ] 在博客项目根目录及子目录运行时自动定位项目；从其他目录可通过 `--project` 指定目标。无法定位项目时明确报错，不使用开发机硬编码路径。
- [ ] 识别既有 Markdown 和 MDX 文章，包括子目录中的文章；文章标识沿用博客现有规则。
- [ ] 默认列出草稿、已发布和已归档文章，每项包含文章标识、标题、状态和发布日期。管理列表不套用网站只展示公开文章的过滤规则。
- [ ] 支持按文章状态筛选；未知筛选值作为参数错误处理。
- [ ] 按发布日期倒序排列，同日按文章标识排序，结果顺序稳定。
- [ ] 元数据校验和读取默认值符合博客现有契约；读取不修改文章，也不回写默认值。
- [ ] 遇到损坏文章时，列表失败并指出具体文件，不把遗漏文章的结果当作完整列表。
- [ ] 默认输出清晰的终端文本；`--json` 模式下成功和失败均在 stdout 输出一个可独立解析的 JSON 结果，stderr 只承载诊断信息。
- [ ] 成功结果包含 `ok` 与 `data`；失败结果包含 `ok` 及带稳定字符串错误码、可读说明的 `error`。参数完整时无需交互，机器输出不混入提示或进度信息。
- [ ] 对本任务涉及的场景落实规格退出码：成功为 0，参数错误为 2，文章数据错误为 3，权限错误为 4，文件读写失败为 5，用户取消为 130。
- [ ] 通过安装后的 CLI 子进程验证项目定位、列表字段、状态筛选、排序、损坏文章、参数错误、权限与读写错误、取消及输出通道。测试只断言可观察结果，并使用临时内容样本。
