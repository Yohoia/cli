# 03: 修改标题并保护其他内容

**What to build:** 用户可以通过 `yoho blog update` 修改目标文章的标题，获得修改结果和新的文章版本。标题之外的内容保持原样，失败时原文件完好，修改后的文章仍被博客正确读取。

**Blocked by:** 02: 查看完整文章与文章版本。

**Status:** ready-for-agent

**Spec coverage:** 用户故事 11、16–25、28–29、31–45，条件更新及冲突场景由 04 完成。本任务复用 02 的目标定位、单篇读取和文章版本约定。

- [ ] 安装后的 CLI 提供 `yoho blog update`，通过文章标识及 `--title` 指定修改；未指定文章版本时，基于当前文件修改标题。
- [ ] 新标题去除首尾空白后为非空单行文本，正确支持中文、引号等正常字符。缺少标题、空白标题和多行标题明确失败，保留原文件。
- [ ] 只修改文章元数据中的标题，正文及正文中的同名标题保持原样。
- [ ] 保留其他元数据及未知字段，包括作者、日期和图片引用；读取时补充的默认值不被顺带写回。
- [ ] 保留标题修改之外的原始注释和排版，不通过重新生成整篇文章丢弃信息或制造无关差异。
- [ ] 不自动修改文章更新时间；文件名、文章标识和访问地址保持不变。
- [ ] 返回文章标识、新标题、修改后的文章版本和是否实际发生修改；更新结果的文章版本与随后查看所得版本一致。
- [ ] 新标题与原标题相同时返回未修改结果，不重写文件，文章版本保持不变。
- [ ] 只检查目标文章，其他文章损坏不阻断正常目标的更新；不存在目标、损坏目标、歧义和路径越界均明确失败。
- [ ] 写入过程不留下半写入文章；权限或文件读写失败时保留原文件，并使用规格约定的错误结果和退出码。
- [ ] 文本和 JSON 输出继续遵循公共契约，参数完整时无需交互。
- [ ] 在临时文章副本上使用安装后的 CLI 验证标题校验、实际修改、无修改结果和失败行为，比较文件以确认所有无关内容保持原样，并验证相同标题没有触发写入。
- [ ] 使用博客实际内容加载逻辑，在显式本地内容模式下读取已修改的临时文章，确认新标题生效且已有内容格式保持兼容。
- [ ] 所有写入验收均使用临时副本，真实文章保持不变。
