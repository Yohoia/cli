# 04: 按文章版本执行条件更新

**What to build:** 本地产品可以携带查看时获得的文章版本更新标题。版本仍匹配时完成更新，版本过期时获得明确冲突结果并保留当前文件；终端直接更新行为继续可用。

**Blocked by:** 03: 修改标题并保护其他内容。

**Status:** ready-for-agent

**Spec coverage:** 用户故事 26–28、35–42、45。本任务复用 03 的完整标题更新流程，以及已由 02 提供的文章版本。

- [ ] `yoho blog update` 接受 `--if-match` 指定文章版本；版本与当前文章匹配时，按既有标题更新规则完成操作并返回新版本。
- [ ] 指定版本与当前文章版本不符时返回稳定的冲突错误，退出码为 3，当前文件及其文章版本保持不变。
- [ ] 标题、正文或其他元数据变化后，基于此前文章版本的更新会发生冲突。
- [ ] 条件检查同样适用于没有实际标题变化的请求，过期版本不能通过相同标题请求绕过冲突检查。
- [ ] 两个携带相同旧版本、请求不同新标题的并发 CLI 条件更新，至多一个成功写入，另一个报告冲突；文件保持完整。
- [ ] 未指定 `--if-match` 时，保留 03 已交付的基于当前文件修改标题的行为。
- [ ] 条件更新成功和失败均支持文本、JSON 输出和非交互调用；输出通道、内容保护和写入失败行为继续符合公共契约。
- [ ] 通过安装后的 CLI，在临时副本上验证查看后更新成功、文章变化后旧版本失败、当前版本成功、相同标题的过期版本请求、并发条件更新以及无条件更新回归。
- [ ] 完成后运行四张任务累计的 CLI 验收，确认本地包中的列表、查看、标题更新和条件更新均可使用，且没有新增真实文章写入。
