# npm 分发与环境诊断

2026-10-28：用户要求落实 npm 分发、版本发布流程、安装文档和环境诊断，并明确选择包名 `@yohoia/cli`、MIT 许可证。该规格扩展远程博客里程碑中未纳入的公开 npm 分发范围；不改变文章 API、Skill 来源、安装位置或凭据存储契约。

## 分发

- 首个准备发布的版本为 `0.8.0`，命令名保持 `yoho`，Node.js 最低版本保持 24。
- 安装、更新、临时运行分别使用 `npm install -g @yohoia/cli@latest`、相同安装命令和 `npx --package=@yohoia/cli@latest yoho`。
- 从旧 `yoho-cli` 迁移时先卸载旧包，再安装新包，避免同名命令冲突；不清理配置、系统凭据或已安装 Skill。
- 发布包只包含构建产物、包元数据、许可证、README 和其配套文档及图片。安装时不构建、不安装开发依赖、不执行额外安装脚本。
- `v<version>` 标签必须严格匹配包版本；稳定版本使用 `latest`，预发布版本使用 `next`。不接受构建元数据或非标准数字版本。
- GitHub Actions 先在 macOS 完成类型、结构、格式、完整回归及打包安装验证。npm 和 GitHub Releases 使用同一个已验证 tarball 与 SHA256 校验文件。
- npm 发布使用 GitHub OIDC。npm 上已有同版本时，仅在 SHA512 integrity 与待发布包完全一致时允许继续补齐 GitHub Release；不同内容及注册表查询异常必须失败。
- 当前请求授权仓库内实现与本地验收；npm 账号/命名空间配置、实际发布、推送版本标签需要后续明确执行。

## 环境诊断

- `yoho doctor` 检查 Node、Git、OpenSSH、Codeup SSH 选择及 PageHush 地址配置。
- 默认只读检查；不运行自定义 SSH 命令、不访问 Codeup 或 PageHush、不读取私钥内容或设备令牌、不写配置。
- 保留 `--server`、`YOHO_SERVER`、保存配置与默认地址的优先级。缺少 Git/SSH、明确指定的私钥不可读或服务配置无效属于失败；需要在线核实权限的项目为警告。
- 警告不使检查失败。通过返回退出码 0；发现失败项返回退出码 2。`--json` 的 stdout 始终是单个 `ok/data` 或 `ok/error/data` 结果，并在失败时保留完整检查列表。
- 取消继续遵循退出码 130。外部版本探针有超时，不应等待网络或用户输入。

## 验收

- 通过真实安装包检查全局安装、离线 npx、同名包升级、旧包名迁移、卸载及配置保留；使用临时前缀和配置，不改用户实际安装。
- 覆盖诊断成功、工具缺失、不可读私钥、损坏配置、服务覆盖优先级、JSON 通道及私钥/令牌不被读取。
- 发布标签不匹配必须在构建或写入发布包之前失败。执行 `pnpm check`、`pnpm format:check` 和完整回归。
