## Standards

初审报告有两项：

1. **P2，边界校验缺失。** PageHush 列表查询仅声明 TypeScript 类型，重复的 `q` 查询参数实际为数组，导致 `q.replace` 抛错并返回 500。违反 TypeScript 技能关于外部数据在边界进行运行时校验的规则。修正为 TypeBox 查询 schema，非法输入返回 400。
2. **P2，Primitive Obsession 设计判断。** PageHush 用正文中的路径子串认定本站素材，外站同路径图片被错误拒绝。修正为解析实际 Markdown/HTML 资源，按完整地址及本站 origin 判定素材身份；提交与回收共用同一规则。

修正后的 CLI 复审又发现一项：恢复查询收到格式错误的响应时，直接返回协议错误，丢失请求编号。修正为独立处理查询失败与已确认的业务结果；不能确认写入结果时保留原编号及恢复提示。真实 HTTP 回归覆盖格式错误、503、401，以及后续同编号恢复，不重复写入。

PageHush 修正复审还发现本站协议相对地址和含 `..` 的路径未被素材识别器标准化，真实回收会误删文章引用的对象。已统一使用带基址的 URL 解析，并补充真实路由与回收回归。最终独立复审确认 URL 来源、加锁和回收规则一致；CLI 恢复及关联元数据事务保护也未发现新的直接错误。

## Spec

初审报告有两项：

1. **P2，外站链接与代码示例误判。** 规格要求代码示例不参与素材上传、HTTP(S) 图片原样保留。服务端整段正文的正则扫描与这些要求冲突。修正与 Standards 第二项共用，新增真实路由回归，并保持真正本站素材的引用保护。
