# Yoho CLI 远程博客管理

Status: ready-for-agent

## Problem Statement

作者的博客文章以阿里云服务器上的 PageHush 为权威来源，当前 CLI 0.2.0 管理本地文章，不能直接完成实际文章库的管理。继续维护本地文章并另行同步会增加重复数据与冲突处理，无法满足作者通过终端直接管理线上内容的目标。

作者希望从终端列出、查看、新增、发布和软删除远程文章。新增以一个本地 Markdown 文件路径为输入，文章中的本地配图需要进入 PageHush 现有的 MinIO 存储。终端登录、网页同时编辑、网络超时和图片部分上传失败时，也必须能判断操作结果，保护已有内容。

## Solution

提供以 PageHush API 为唯一数据来源的 `yoho blog` 命令组，包含 `list`、`show`、`create`、`publish` 和 `delete`。作者通过设备码在 PageHush 网页授权 CLI，后续复用有效设备令牌；本地产品及脚本沿用文本、JSON 和退出码契约。

`create` 接收一个本地 `.md` 文件路径，提取文章信息、预检正文及配图，通过 PageHush 素材 API 上传本地内嵌图片，在内存中改写图片地址后创建草稿。发布是独立操作；发布和删除都要求文章版本，冲突由服务器原子拒绝。源 Markdown 与图片保持只读。

最终交付以远程管理替换原有本地文章管理。允许修改 PageHush 后端与网页，并保留现有剪藏扩展创建草稿的兼容性。实际验收使用临时 API、隔离数据库与素材存储，不写入线上文章。

## Implementation Decisions

### 目标和配置

- 保留 TypeScript、Node.js、pnpm、Commander 和现有文本/JSON 输出边界。命令适配层、远程文章服务、HTTP 适配、文档解析、凭据存储和操作记录各自负责明确职责；不保留本地文章库适配作为第二运行模式。
- 默认服务为 `https://pagehush.yohoia.cn`。显式 `--server` 优先于服务地址环境变量，环境变量优先于已配置默认值与内置默认地址；只维护一个默认服务，不引入命名 profile。
- 服务地址先规范化，凭据与操作记录使用同一规范化服务身份隔离。业务命令不再依赖博客项目根目录、内容目录或本地文章相对路径身份。
- 命令与帮助以远程语义为准。旧本地编辑命令和仅适用于本地文章库的选项不再执行文件修改，提供明确的迁移提示。

### 设备授权和权限

- PageHush 提供 OAuth 2.0 设备授权流程，网页沿用现有作者登录以批准或拒绝设备，CLI 作为公开客户端不内嵌客户端密钥。
- 登录显示授权网址、设备码与操作提示，并尝试打开外部浏览器；无法打开时仍可手动授权。轮询遵守服务端间隔，能处理待批准、降速、拒绝、过期和用户取消；只有成功取得令牌才保存凭据。
- 默认设备授权有效 30 天，过期重新登录，本期不增加自动刷新。正常业务命令结束不撤销授权。
- 服务器只授予列出、查看、创建草稿、发布、软删除文章和文章上传所需的内嵌图片上传权限。设备不能借通用更新接口修改正文、标题、日期、任意状态、标签、主题或封面，也不能使用独立素材管理能力。
- 图片上传权限绑定文章上传操作，仅允许 `inline_image`；不能依靠 CLI 隐藏命令来代替服务端授权检查。该授权约束同时保护现有通用 API 入口。
- 令牌按服务地址存入系统凭据存储，不可用时明确失败，不静默降级为明文文件。环境变量提供的有效设备令牌用于非交互调用，不落盘；凭据、访问码和存储密钥不得出现在日志与操作记录中。
- 提供登录、授权状态查询和注销入口。注销在服务端撤销当前授权后删除本机凭据；撤销失败保留凭据供重试，并明确告知仍未确认撤销。
- 网页提供设备授权元数据列表和撤销入口；不显示可复用令牌明文。撤销和过期后，后续 API 请求被拒绝。

### 列表、详情与文章身份

- UUID 为权威身份，CLI 同时接受服务器完整短 ID；短 ID 必须精确解析为同一 UUID，不做前缀匹配。标题、可变 slug 和本地文件路径不能充当远程文章标识。
- 列表默认只含未删除的草稿和已发布文章，支持状态、关键词、页大小和翻页参数；默认每页 20 篇，不暗示当前页就是完整文章库。
- 排序以服务器记录更新时间倒序为主，同值以稳定标识确定顺序；分页结果给出后续页所需信息，状态与关键词筛选在分页之前执行。
- 列表提供 UUID、短 ID、标题、状态、文章版本及可用的日期信息。草稿创建时间与首次发布时间保持区别，不把草稿创建时间宣称为已发布时刻。
- 详情返回完整 Markdown、服务器元数据、稳定标识和文章版本。版本由服务器产生，是不透明的比较值，不使用客户端文件散列、发布时间或标题替代。
- 删除后的文章在正常列表、详情和博客读取中不可见；不存在或已删除目标给出稳定错误。

### Markdown 文件新增

- `create` 接收一个 `.md` 文件路径，本期不扩展为目录批量导入、MDX、标准输入或独立正文参数。相对文档路径以调用目录为基准，支持绝对路径；文件必须存在、可读、为普通文件且是有效 UTF-8。
- 支持普通 Markdown 与 YAML frontmatter。仅导入 `title`、`description`、`language`；标题按非空 `title`、代码块之外的首个一级标题、去扩展名文件名依次回退。明确填写但类型错误的字段不能静默忽略。
- 标题为非空单行文本，描述为文本，语言沿用服务器支持的中文或英文。默认中文；标题、描述长度遵守 PageHush 现有上限，解析或字段错误在远程写入前报告。
- 缺少有效描述时，确定性地从正文提取纯文本摘要，遵守描述长度上限，不调用模型或访问网络。如果不能得到有效摘要则明确要求补充描述，不提交必然无法发布的文章。
- 忽略导入白名单以外的 frontmatter 字段，并列出未导入字段；不把本地日期、作者、状态、标签、主题、封面或 slug 自动传给远程 API。
- 移除 frontmatter 后保留原正文，包括作为标题来源的一级标题；唯一进一步改写是已确认的本地内嵌图片地址替换，不重新排版全文或修改代码示例。
- 正文为空或仅空白，在上传任何图片及创建文章前拒绝。文档与素材均只读，源文件不写入远程 UUID、版本或改写后的链接。
- 远程格式为 Markdown，创建结果始终是草稿，由服务器生成 slug 与稳定身份。每次主动运行 `create` 都创建新文章，不按本地路径或内容散列覆盖已有文章。

### 本地图片随文上传

- 识别标准 Markdown 行内图片语法，准确处理路径、转义和代码块边界；不把代码示例里的图片语法当作待上传图片。本期不承诺 HTML 图片标签、引用式图片定义或任意 MDX 组件导入；不支持的本地资源引用明确报出，不静默留下损坏链接。
- 本地相对图片路径以 Markdown 文件目录为基准，可包含现有文档采用的父目录引用。只读取正文明确引用的图片，不扫描或上传整个目录。
- 图片预检覆盖存在性、可读性、文件类型、大小与支持的格式；支持 JPEG、PNG、WebP，单张最多 5 MiB。发现任一无效本地图片时，在远程写入前终止并指出引用位置。
- 同一文档中重复引用同一张本地图片只上传一次，所有对应引用使用同一素材。该去重及上传重试保证不等于跨全部历史文章的全局图片查重。
- 通过受设备授权保护的 PageHush 素材 API 上传，由服务端验证图片并写入 MinIO；CLI 不使用 MinIO endpoint、对象键或存储密钥。素材返回稳定的 PageHush 访问地址，正文不保存会过期的签名 URL。
- 在内存中的正文副本替换成功上传图片的地址，保留图片说明、正文其他部分和源文件。所有所需图片成功就绪后才能创建草稿；图片失败时没有部分文章创建。
- HTTP(S) 远程图片和已有 PageHush 素材地址直接保留，不下载或重新归档；不校验外站未来的可用性。形如 `/v1/assets/<id>/content` 的既有素材地址优先识别为 PageHush 素材，不能误当本地绝对路径。文章内锚点保留。普通本地附件和其他 Markdown 文档不递归上传，未解决的本地资源链接应报出并阻止提交。
- 图片上传使用文章操作编号下稳定的子请求身份及图片指纹。相同请求重放返回已有结果，不因网络重试新增素材；相同身份携带不同内容明确冲突。
- 数据库与对象存储不能被假定为一个原子事务。服务端跟踪本次上传的素材与文章提交结果，支持中断恢复，并在至少七天的宽限期之后清理失败操作遗留且仍未引用的素材。
- 回收只针对该流程拥有的孤立素材，不清理已提交文章、草稿、软删除文章或其他文章仍引用的素材；对象删除失败可重试，不以数据库标记代替实际对象清理。回收与文章提交需协调，防止删除正在提交或恢复中的素材。
- 博客继续使用既有 PageHush 素材引用及公开图片代理规则，草稿素材不因此自动变成匿名公开资源。

### 请求去重与不确定结果

- 每个逻辑写操作生成稳定请求编号，服务器原子记录身份、请求指纹和结果。同一编号的并发请求或重放最多提交一次；同一编号与不同目标、参数、正文或素材内容不兼容。
- 本次图片上传与最终草稿创建属于同一个文章上传流程；恢复已有流程复用编号，不能通过再次运行一个新的 `create` 来冒充重试。
- CLI 保存服务地址、操作编号、输入指纹及恢复所需最少元数据，不保存正文、图片字节或凭据；新增完成后返回远程文章标识和文章版本。
- 提供按请求编号查询操作结果的 CLI/API 入口；读取可有限重试，写入超时后先查询结果。能够确认成功时返回原结果，确认失败时返回错误，仍不能确认时返回稳定的结果未知错误及查询方式，不宣称失败或自动新建。
- 服务端操作结果至少保留七天。超过保留期而结果无法确认时，提示人工核对；不能将已过期或未知的旧编号静默当新请求重新执行。图片清理窗口与可恢复操作窗口协调。
- 发布与删除同样支持去重与结果查询；已成功请求重放返回原结果，不因为其自身已改变文章版本而错误报冲突。
- 取消或进程终止如果可能发生在远程提交之后，必须保留操作编号并提示结果可能未知，不能以本地取消推断服务器已回滚。

### 发布、软删除与网页并发

- `publish` 要求目标文章标识与 `--if-match` 文章版本；服务端原子判断版本后发布，缺少条件明确失败。首次有效发布由服务器记录实际发布时间，不导入本地发布日期。
- 使用新请求编号操作时，即使文章已发布也必须先通过版本检查。版本匹配且已发布返回 `changed=false`，不改日期、文章版本或更新时间；与原请求编号重放区别处理。
- 服务器统一检查发布时标题、正文、描述非空及其他现有合法性规则。网页与 CLI 共用规则，CLI 不通过任意字段更新接口绕过发布限制。
- 删除预览由 `--dry-run` 触发，返回标题、状态、版本并明确尚未删除；不写入文章、不预留目标。与 `--yes` 同时出现时仍只预览。
- 实际删除要求 `--yes` 与 `--if-match`，即使未预览也必须提供已取得的版本。服务器原子校验后设置软删除标记，保留记录与文章素材；版本冲突不删除任何内容。
- 网页所有文章修改、发布/撤回及删除调用迁移为带服务器版本的请求，后端不接受缺少版本条件的旧写请求。网页冲突明确提示，不自动重试覆盖，保留尚未保存的输入。
- 网页与后端协同升级；现有剪藏扩展创建草稿继续兼容，不强迫它增加本期 CLI 专用参数或改变图片失败策略。

### 输出与错误

- 默认文本输出。`--json` 时成功和失败各输出一个可独立解析的结果到 stdout；日志、进度、浏览器提示和未导入字段提示不污染 JSON，诊断写 stderr。
- 沿用 `ok/data` 与 `ok/error` 结果结构、稳定字符串错误码和非零失败退出码。认证、权限、版本冲突、图片校验、网络失败与结果未知应能区分。
- 沿用现有退出码：0 成功，2 参数错误，3 文章数据错误或版本冲突，4 认证/权限错误，5 文件或远程 I/O 失败，130 用户取消。错误包含面向人的原因和可执行的下一步，结果未知包含请求编号。
- 除设备授权明确需要网页交互外，参数完整的业务命令不等待提示确认；删除显式确认由参数表达。

## Testing Decisions

- 用户在 Q20 已确认主要边界：打包并安装后的真实 CLI 子进程，通过 HTTP 访问临时 PageHush API，使用独立临时数据库、隔离凭据/配置和素材存储；观察 stdout、stderr、退出码及 API 回读结果。
- 优先复用当前 CLI 安装测试和 PageHush 可注入数据库与素材存储的测试边界。PageHush 既有迁移、PGlite、FakeStorage 与真实 Fastify 路由可验证协议和状态，不把客户端 HTTP mock 当作完整验收。
- 网页设备批准、授权撤销和编辑冲突使用浏览器连接隔离真实 API 验收。现有仅 mock API 的网页测试可辅助覆盖提示，但不能证明服务端授权或并发保证。
- 真实并发使用独立临时 PostgreSQL 和多个客户端验证原子条件写入、同请求并发去重、文章提交与素材回收协调；仅 PGlite 或单请求顺序测试不能替代这些证据。
- 好测试断言使用者可观察结果及持久化结果，不绑定内部函数、私有数据结构或特定解析库的调用方式。测试用自建文档、临时图片与数据库，不读取生产 `.env`、凭据或真实内容库。
- 设备授权验证成功、拒绝、过期、取消、重复批准、轮询降速、令牌过期、撤销、凭据存储不可用、环境变量令牌不落盘以及跨服务凭据隔离。
- 权限验证直接绕过 CLI 调用 API，证明设备不能编辑正文、撤回发布、管理标签/主题、上传任意类型素材或独立使用其他管理端点。
- 读取验证 UUID/短 ID 一致、状态与关键词先筛选后分页、默认每页 20 篇、完整详情、稳定排序、未删除可见范围及文章版本。
- 新增验证普通文档、frontmatter、标题三层回退（`title`、首个一级标题、文件名）、摘要生成、未导入字段提示、语言、中文/空格路径、UTF-8、空白正文、非法字段、源文档逐字节不变及主动重复创建新草稿。
- 配图验证相对/父目录路径、重复引用、远程 URL 保留、代码块跳过、缺图、错误 MIME、超限、不支持引用、部分上传失败、提交失败、重试与未引用素材回收。
- 回收验证至少七天宽限期、所有已提交文章及软删除引用的保留、删除失败后重试、文章提交竞争期间不会误删；不得为了测试而等待七天真实时间。
- 发布和删除验证缺少版本、匹配版本、旧版本、网页/CLI 并发、已发布 no-op、幂等结果重放、软删除后读取不可见、文章记录与素材仍保留，以及网页冲突保留输入。
- 网络测试覆盖提交成功但响应丢失、素材成功但文章失败、同编号不同内容、进程取消、结果查询失败和保留期过后未知结果。断言不会盲目重复创建。
- 最终验收覆盖从设备登录、读取、新增含图片草稿、查看、发布、删除预览、条件软删除、操作查询直至注销的完整链路。源码事实与真实线上部署是否一致另行部署核对，不由隔离测试作保证。

## Out of Scope

- 继续提供本地文章管理模式、本地与远程双向同步、自动覆盖已存在远程文章或按文件路径建立永久同步关系。
- CLI 修改已有文章正文、标题或元数据，撤回发布、归档、恢复软删除和永久删除文章。
- 目录批量导入、MDX 导入、交互编辑器、标准输入正文和原有独立正文参数组合。
- 标签、主题、封面及图片的独立管理命令；本地附件/其他文档递归上传、任意 HTML/MDX 组件图片、远程图片下载归档及全库素材去重。
- CLI 直连数据库或 MinIO、存储访问码或 MinIO 密钥、PAT、浏览器回调登录、自动刷新令牌和多 profile 管理。
- 自动 Git 提交/推送、公开 npm 发布、线上部署、线上文章写入验收以及 Skill 管理与 AI 对话功能。
- 本期跨平台安装验收扩大到 Linux/Windows；交付仍优先在 macOS 验收并采用跨平台接口。
