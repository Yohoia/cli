# 远程博客管理任务拆分草案

Status: ready-for-agent

依据：[已确认规格](spec.md)。本文件供用户核对任务粒度与依赖，用户直接调用 `implement`，按此拆分进入执行；独立任务单已发布到 `issues/`。

按可独立展示的纵向能力拆分，每项同时完成所需协议、服务端行为、客户端行为与对应验证，不按后端、前端、CLI、测试分别建横向任务。下面只列直接依赖，传递依赖不重复列出。

| 编号 | 任务 | 直接依赖 | 完成后可验证的结果 |
| --- | --- | --- | --- |
| 01 | 设备登录并读取远程文章列表 | 无 | 安装后的 CLI 发起设备授权，网页批准或拒绝；签发默认 30 天有效的受限令牌，按服务地址保存，登录后能读取第一页远程文章。覆盖取消、凭据存储失败、环境变量令牌与服务覆盖。 |
| 02 | 完整查询文章列表与详情 | 01 | UUID 与短 ID 定位同一文章，支持状态、关键词、每页默认 20 篇及翻页；建立持久化的服务器文章版本，相关修改会更新版本，列表与详情返回版本，详情含完整正文。文本、JSON、错误和有限读取重试可验证。 |
| 03 | 授权状态、注销与网页撤销 | 01 | 查询当前授权状态，验证默认 30 天过期；CLI 注销撤销当前授权，失败保留凭据；网页列出并撤销设备，过期或撤销后的请求被拒绝。 |
| 04 | 上传无本地配图的 Markdown 草稿并查询结果 | 01 | 从 `.md` 路径提取字段，上传前拒绝空正文与无效输入，源文件不变；主动重复执行新增，网络重试去重；超时通过操作编号查询结果，至少七天可恢复且本地不存正文。 |
| 05 | 网页与 API 共同保护文章版本 | 02 | 使用 02 提供的服务器文章版本，网页编辑、发布/撤回和删除都带版本，服务器原子检查；旧版本或缺条件明确失败，网页保留未保存输入，剪藏扩展新增兼容。临时 PostgreSQL 验证并发仅一方成功。 |
| 06 | 按指定版本发布文章 | 04、05 | CLI 独立发布，服务端统一字段校验与首次发布时间；匹配版本的重复发布不修改，过期版本拒绝，写入超时能查询原请求结果。 |
| 07 | 预览并按指定版本软删除 | 04、05 | 预览显示标题、状态与版本；执行必须显式确认并提供版本。软删除后正常读取隐藏，记录与素材保留；冲突和未知结果可以判断。 |
| 08 | 自动上传 Markdown 本地内嵌图片 | 04 | 相对路径预检、重复引用复用、素材幂等上传、内存正文改写后创建草稿，源文件不变；任一图片失败不创建文章，CLI 只取得文章内嵌图片上传窄权限。 |
| 09 | 安全回收失败上传遗留素材 | 08 | 至少七天后回收失败操作仍未引用的素材，保留所有已提交文章、草稿与软删除文章引用的图片；回收与提交并发安全，存储删除失败可重试。 |
| 10 | 移除本地模式并完成安装后整体验收 | 03、06、07、09 | 完成旧本地文章模式和仅本地选项的退出，更新使用说明；真实安装包在临时 API、数据库、凭据与素材环境跑通登录、查询、带图新增、恢复、发布、预览、软删除和注销。 |

## 依赖说明

- 02 与 03 都只依赖设备登录；查询能力和授权管理可以分别推进。
- 02 负责引入、持久化并返回文章版本，文章修改会产生新版本；05 在这一版本契约上增加原子条件写入，因此 05 对 02 的依赖来自共享契约，不只是开发顺序。02 完成时尚不宣称具备并发覆盖保护。
- 04 不依赖完整列表与详情，可以直接通过新增响应和 API 回读验收；其操作记录与查询能力供后续写命令复用。
- 05 可以使用网页现有草稿验收，不依赖 CLI 新增，因此可与 04 并行。
- 06、07 依赖 04 提供的操作去重/查询和 05 提供的原子版本契约，不依赖图片上传。
- 08 是在 04 已有完整新增链路上增加本地配图的完整行为；04 阶段只拒绝尚不支持的本地资源，最终范围由 08 补齐。
- 09 在 08 确定了操作与素材关联后完成存储回收，08 阶段不擅自删除残留对象。
- 10 通过传递关系覆盖全部能力，完成之前不发布一个仍保留本地双模式的最终版本。

## 各任务共用的验收边界

- 每项任务都包含其行为所需的服务端、CLI 或网页改动与验证，不把测试集中推迟到 10。CLI 使用打包安装后的子进程和真实 HTTP；网页连接隔离 API，观察实际输出、退出码及持久化结果。
- 临时数据库、凭据配置与 FakeStorage 和生产隔离，不读取生产配置或对线上文章执行写入。04 的请求去重、05 的版本竞争、08 的素材上传去重与 09 的回收竞争分别取得临时 PostgreSQL 多连接证据，不能只用 PGlite 或 HTTP mock 代替。
- 每项新增命令或错误沿用规格的文本、JSON 和退出码契约；JSON stdout 不混入日志，参数完整时不增加业务交互。任务完成后记录对应验收证据。

## 发布任务单时必须展开的验收条件

1. **01：设备登录。** 覆盖手动网址回退、待批准、降速、拒绝、超时、取消、重复批准及只有成功才保存凭据；服务地址覆盖与规范化隔离、系统凭据失败不降级明文、环境变量令牌不落盘。直接调用 API 验证设备权限受服务器限制，未完成的写能力不能通过通用接口绕过。
2. **02：完整查询。** 版本为服务器持久化的不透明比较值，读取不修改版本；版本推进规则为 05 的条件写入提供基础。验证完整短 ID 而非前缀、筛选先于分页、稳定排序、草稿与首次发布日期的区别，以及不存在或已删除目标的稳定错误。
3. **03：授权生命周期。** 状态查询不泄漏令牌；验证令牌过期、网页撤销和 CLI 注销后拒绝访问。注销只有确认服务端撤销后才删除本机凭据，失败保留凭据并允许重试。
4. **04：无本地配图的新增及恢复。** 完整覆盖文档字段与标题回退、摘要、UTF-8、中文和空格路径、空正文预检、源文件不变、远程图片及已有素材地址保留；尚不支持的本地资源先拒绝。验证同编号并发最多创建一次、不同内容冲突、响应丢失、进程取消、未知结果查询及至少七天结果保留；旧编号过期后不能当作新请求重做，本地操作记录不保存正文或凭据。
5. **05：原子版本保护。** 使用网页现有草稿验证全部文章修改、发布/撤回及删除入口，缺条件与旧版本均失败；两个客户端基于同一版本的竞争不能同时覆盖成功。浏览器冲突后保留输入，现有剪藏扩展创建草稿兼容。
6. **06：条件发布。** 服务端统一校验标题、正文和描述，记录首次有效发布时间；新编号必须检查版本，匹配版本的已发布操作返回 `changed=false`，日期、更新时间和版本不变。成功编号重放返回原结果，不因自身改变版本而冲突，超时按编号查询。
7. **07：条件软删除。** 实际删除必须有 `--yes` 和 `--if-match`；`--dry-run` 仅预览，和 `--yes` 同时传入仍不删除。验证预览不锁定目标、过期版本拒绝、新编号检查版本、成功编号重放、未知结果查询，以及删除后正常读取隐藏但文章记录和素材保留。
8. **08：内嵌图片上传。** 验证相对及父目录路径、JPEG/PNG/WebP 与 5 MiB 上限、同图复用、代码示例跳过、所有本地资源先预检及任一图片失败不创建文章。保留 HTTP(S) 与已有素材地址，只改内存正文；直接 API 验证上传绑定文章操作且仅允许内嵌图片，不能取得 MinIO 密钥或独立管理素材。覆盖相同素材请求并发去重、不同内容冲突、部分上传与提交失败的恢复，以及草稿素材沿用现有访问保护。
9. **09：遗留素材回收。** 只回收本流程拥有、失败遗留且宽限期至少七天后仍未引用的素材；草稿、软删除及其他已提交文章引用均保留。实际对象删除失败可重试，提交或恢复与回收并发时不误删；测试使用可控时间，不等待七天真实时间。
10. **10：最终安装交付。** 移除本地文章管理和旧选项的执行路径，更新远程帮助、迁移提示和使用说明；安装包在隔离环境贯通设备登录、列表/详情、带图新增、结果恢复、条件发布、删除预览、条件软删除及注销，并记录 CLI 与 PageHush 的配套版本。

## 执行

用户调用 `implement` 后按上述十项开始实现。独立任务单位于 `issues/`，任务的验收结果追加在各自 Comments 中，未勾选的验收项不代表完成。
