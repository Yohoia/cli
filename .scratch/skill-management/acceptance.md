## 恢复与边界验证

- 使用真实目录权限导致目标写入失败，验证首次安装整批回滚与更新按目标恢复的不同规则。
- 使用进程文件大小限制，让目标已经替换后、安装记录写入时发生真实 I/O 失败；验证该目标原文件及空提交关联恢复，而其他目标仍更新成功。
- 杀死持有目标锁的更新进程，验证全局锁和目标锁的失效处理；同时启动两个重试，验证互斥，不允许两者同时回收并写入。
- 用遗留备份、目标缺失及失效回收门验证恢复诊断，检查原内容保留、路径准确；回收门改名留存后可重试，不删除安装配置或 Skill 内容。
- 构造越界归档、坏压缩包、本地链接和同名歧义，检查相邻哨兵内容不变。私有令牌只存在于测试边界，不写入来源缓存或安装记录。

## 验收范围

- GitHub 使用本机可控协议服务，元数据、提交及归档为真实 HTTP 数据，gh 只在第三方授权边界模拟。测试不依赖 GitHub 在线状态，也不使用本人的真实 GitHub 凭据。

- 不包含全局替换本机已有 yoho、公开 npm 发布或远程推送。发行包用于后续用户安装；Git 提交按 implement 指令写入当前分支。
