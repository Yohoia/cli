# Skill 管理需求讨论

日期：2026-10-24。

Q1–Q27 已确认，需求访谈完成。以下先汇总当前结论，再保留逐轮讨论记录；早期建议被后续回答修正时，以当前结论和后续确认项为准。[正式规格](spec.md)已生成并标为 ready-for-agent，九份任务单已发布并完成实现，详见[验收记录](acceptance.md)。

## 当前确认的行为

1. 本轮包含来源管理、Skill 列表、安装和更新；博客远程编辑后移。
2. 初始来源为 `Yohoia/yoho-standard-readme`、`Yohoia/yoho-retro-poster`、`Yohoia/yoho-speckit`。每仓库根目录一个 SKILL.md；安装名称使用其 name，因此第三个安装为 speckit。
3. 来源配置按当前用户保存，各项目共用，支持添加、查看、移除和刷新。增加新仓库不要求更新 CLI，也不自动扫描整个 GitHub 账号。
4. 来源列表显示 Skill 总数、名称、描述及来源。目标选择后分目标显示已安装状态；本次勾选与已安装标记分开。部分目标已有时只补装缺失目标，全部已有时安装列表禁选。
5. 支持项目级和用户级安装，默认当前项目；项目级默认当前工作目录，可指定其他项目路径。目标多选，提供 `.claude/skills`、`.agents/skills`、`.codex/skills`，相同物理目录只处理一次，执行前展示最终路径。
6. 安装完整 Skill 内容与附属资源，排除 Git 元数据；不自动运行脚本或安装依赖。默认分支最新提交在每次操作开始时固定，同一来源的多个目标使用同一份内容。
7. CLI 记录安装来源、位置和提交。更新支持全部、单个或多个 Skill，统一由 CLI 负责；交互多选与非交互参数调用均支持，并提供 JSON 输出。
8. 手动安装按 SKILL.md 的 name 在登记来源中精确匹配，唯一匹配才自动建立来源关联。无匹配或歧义时跳过并报告，不猜测。
9. 更新以仓库为准，覆盖本地修改、恢复本地删除的文件、删除仓库没有的本地新增文件。即使提交未变，也检查本地内容，不能将有修改的安装当成无需更新。
10. 更新全部仅处理所选范围和目标中的已有安装，不补装缺失目标。单项失败继续处理其他项，报告成功、未变化和失败；有失败时返回非零退出码。
11. 首次批量安装先下载检查全部内容；写入失败回滚本次新增内容。更新则按目标恢复：成功目标保留，失败目标恢复到写入前。两种流程都明确报告无法清理或恢复的路径。
12. 移除来源保留文件与原始来源记录，暂停该来源更新；重新添加后恢复更新能力。
13. 来源暂不可访问时保留上次列表并标记不可用，其他来源继续使用；首次获取失败明确报告，不冒充零个 Skill。安装和更新必须成功取得当前提交，不把缓存当最新。
14. 公开仓库允许未登录下载；私有来源复用本机 gh 登录，不另存 GitHub 凭据。无权限来源明确标记且不可选择。用户计划自行将 readme 仓库公开，该操作不属于 CLI 实现任务。
15. 首版优先 macOS，以临时目录完成安装包验收，不改动用户现有真实 Skill。暂不包括集合仓库、任意自定义目标目录、卸载、旧版本回退、定时更新、Linux/Windows 完整验收。

## 已确定的方向

- 博客模块暂时停留在现有远程管理能力，远程编辑放到后续。
- 本轮范围为来源管理、查看可安装 Skill、多选安装和更新。更新由 CLI 统一负责。
- Skill 来源已由用户指定为三个 GitHub 仓库：`Yohoia/yoho-standard-readme`、`Yohoia/yoho-retro-poster`、`Yohoia/yoho-speckit`。
- 列表展示可安装 Skill 的总数，终端支持一次选择多个 Skill。
- 安装时允许多选目标工具，目录映射与兼容目标见第二轮结果。

## 设计树

- 来源与目录：实际仓库、公开或私有、目录布局、发现规则、分支及版本选择。
- 查看：总数的含义、名称与描述、筛选、不可用条目和错误处理。
- 选择：Skill 多选、目标工具是否多选、无终端时的调用方式。
- 安装位置：项目级或用户级、工具目录映射、自定义位置。
- 安装行为：复制内容范围、同名冲突、重复安装、批量失败与取消处理。
- 交付：支持平台、隔离验证、文档与验收边界。

## 三个来源的目录核验

- 三个仓库的 main 分支均只有一个根 SKILL.md，没有嵌套 Skill、符号链接或 Git 子模块，因此当前目录可列出三个 Skill。
- frontmatter name 分别为 `yoho-standard-readme`、`yoho-retro-poster`、`speckit`；最后一个仓库名是 yoho-speckit，但 Skill 的安装标识是 speckit。安装目录命名规则待正式确认。
- 各 Skill 都带附属资源。speckit 的脚本依赖同目录的脚本和 assets；静态检查的 36 条本地 Markdown 链接均能在仓库内解析。完整目录复制与不运行脚本的既定方案适用。
