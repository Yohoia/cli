# Yoho CLI Skill 来源、安装与更新

Status: ready-for-agent

## Problem Statement

作者已将 Skill 保存在多个 GitHub 仓库中。用户需要逐个寻找仓库、下载完整资源，并手动复制到不同 Agent 的发现目录；很难知道当前共有多少 Skill、哪些目标已经安装，以及安装内容是否与仓库一致。新增仓库后，现有 CLI 也没有获取新 Skill 的入口。

同一 Skill 可能同时安装在项目级、用户级和不同 Agent 目录中。手动复制的安装没有来源记录，本地文件又可能被修改，更新时既容易漏掉目标，也难以判断失败后哪些目录仍可使用。作者希望由 CLI 统一管理这些流程，以仓库为内容权威，能够批量安装和更新，并获得准确的逐目标结果。

## Solution

在现有 Yoho CLI 中提供 `yoho skill` 命令组，管理来源、展示目录、多选安装与更新。博客模块保持本轮之前的远程管理范围，远程编辑留待后续。

初始登记三个来源：

| 来源                          | 当前核实的 Skill 名称  |
| ----------------------------- | ---------------------- |
| `Yohoia/yoho-standard-readme` | `yoho-standard-readme` |
| `Yohoia/yoho-retro-poster`    | `yoho-retro-poster`    |
| `Yohoia/yoho-speckit`         | `speckit`              |

首版每个来源仓库根目录包含一个 `SKILL.md`。用户可以登记新仓库、刷新列表，无须重新发布 CLI。来源配置按当前用户保存，各项目共用。

交互安装先选择项目级或用户级范围及目标，再展示带名称、描述、来源和逐目标安装状态的 Skill 列表。用户可同时选择多个 Skill 和多个目标；已存在的目标不通过安装命令覆盖，只有部分目标缺失时补装缺失的部分。

| 目标              | 项目级目录                | 用户级目录         |
| ----------------- | ------------------------- | ------------------ |
| Claude Code       | 项目下的 `.claude/skills` | `~/.claude/skills` |
| Codex及通用 Agent | 项目下的 `.agents/skills` | `~/.agents/skills` |
| Codex兼容目录     | 项目下的 `.codex/skills`  | `~/.codex/skills`  |

项目级默认当前工作目录，也可指定其他项目路径。执行前展示完整目标路径。相同物理目录不重复处理。

更新统一由 CLI 负责，支持单个、多个及显式更新全部。手动安装的 Skill 在登记来源中能唯一匹配时自动建立来源关联。更新以来源默认分支的最新提交为准，覆盖本地修改并删除仓库没有的本地新增文件；不要求用户先清理修改。安装和更新都复制完整 Skill 及其附属资源，不运行其中的脚本或安装依赖。

首次批量安装失败时回滚本次新增内容；更新则按目标恢复，成功目标保留，失败目标恢复后继续其他项。交互、参数调用、文本和 JSON 输出共享同一业务行为。

## Implementation Decisions

### 现有 CLI 与能力边界

- 延用当前 TypeScript、Node.js、pnpm、Commander、Zod 和打包方式，不因 Skill 功能改造为新的发布平台或包管理体系。
- 增加独立的 Skill 命令组和来源管理入口，覆盖来源添加、列表、移除、刷新，以及 Skill 列表、安装和更新。命令参数解析和交互适配调用同一业务能力，不能复制两套安装逻辑。
- 分清来源目录与元数据解析、目标发现与安装记录、安装和更新协调、GitHub 获取及终端交互职责。文件布局由实现确定，规格不锁定内部模块数量。
- 延用现有结果与错误输出契约，为批量结果增加可区分的逐项状态，避免用单个成功布尔值掩盖部分失败。博客授权和 Skill 来源授权属于不同服务，不混用凭据。
- 本规格优先于早期探索指南中的 Skill 设想。本期不要求 manifest、SemVer、独立 Registry 或每个 Skill 自带更新器；身份来自根入口文档，内容版本由来源提交标识。

### 来源配置、发现与身份

- GitHub 来源接受仓库标识及对应仓库链接，规范化为稳定仓库身份。初始登记用户指定的三个仓库；初始化不能使用户移除的来源反复出现，重复登记同一来源不产生重复项。
- 来源配置按当前用户持久化，供不同项目使用。来源移除保留安装文件及原始来源身份，但不继续更新；重新登记同一来源后恢复其安装的更新能力。
- 每个来源只识别仓库根部的一个 Skill 入口文档，从 frontmatter 获取 name 和 description，安装名称使用 name。新增来源不能通过遍历嵌套文档意外发现测试样例或其他 Skill。
- 仓库身份、Skill 名称与安装位置分别记录。名称用于展示和手动安装的来源匹配，不能仅靠名称覆盖已经明确记录的来源；同名多来源必须展示来源以便区分，不能静默选择其中一个。
- 元数据缺失、格式错误或名称不能安全用于单级目录时，该来源报告明确错误，不生成有效可安装项。来源内容改变 Skill 名称或与已有记录身份不符时，不静默将已有安装改名或关联到其他来源。
- 手动安装在所选目标中读取入口文档，按 name 与当前登记的来源精确匹配；唯一匹配才自动保存来源关联与实际安装位置，找不到或存在歧义则跳过并报告。来源关联本身不等同于内容更新，不能给未成功更新的目录记录新提交。
- 列表展示已知 Skill 总数及逐项来源状态，缓存条目明确注明未刷新或不可用。必须能区分已知条目数、当前可获取条目及尚未成功读取的来源，不能把首次获取失败显示为权威的零个 Skill。
- 刷新分别处理各来源，保留失败来源上次成功获取的元数据并标注错误；其他来源的成功结果仍可使用。安装和更新必须取得所选来源当前默认分支提交及其内容，失败时不将缓存充作最新版本。

### 获取内容与授权

- 使用 GitHub 默认分支的最新提交，不固定分支名称，不引入 release 或 SemVer 选择。每次操作对同一来源只确定一份提交快照，下载与多个目标均使用该快照，分支中途推进不改变本次内容。
- 公开来源允许未登录获取，不要求所有用户安装或登录 gh。私有来源复用本机 gh 的授权能力，不新增保存令牌的机制；缺少 gh、未登录或无权限时提供可执行的原因提示，避免影响其他公开来源。
- CLI 获取完整 Skill 内容及附属资源并排除 Git 元数据，不运行来源中的脚本、安装钩子或依赖安装命令，不替 Skill 完成首次运行时的密钥及运行环境配置。
- 外部元数据与下载内容在边界校验。拒绝将仓库名称、Skill 名称或归档条目解释成安装目录之外的路径；不得跟随来源中的链接写出目标边界，或因畸形下载覆盖相邻文件。
- 日志、来源缓存、安装记录和 JSON 结果不保存或泄露 GitHub 令牌；授权只用于相应 GitHub 获取过程，不发送给无关地址。

### 目标选择、列表与交互

- 同时支持项目级与用户级范围；默认项目级，以当前工作目录作为默认项目位置，允许显式指定其他项目。用户级目标依据当前用户位置解析，不能把项目位置误作用户位置。
- 本期只有三种已确认的标准目标，不新增任意安装目录。相同物理位置去重；安装、更新或恢复均只允许处理所选目标中的具体 Skill 安装，不能扩大到其父目录。
- 先确定范围与目标，再展示相应安装状态。待安装勾选、已有安装、缺失和来源不可用等状态必须可区分，不能用预勾选表示已安装。
- 对选择的所有目标都已存在的 Skill，交互安装禁选；仅部分已有则允许勾选，仅向缺失目标安装。非交互调用遵守相同规则，并将已有目标列为跳过，而不是覆盖。
- 同名目录存在即保护原内容，包括手动复制的目录；已有但无法解析的目录不能冒充可自动接管的有效 Skill。安装时遇到这种占位仍不覆盖，更新时报告识别问题。
- 安装、更新支持终端多选和完整参数的非交互调用。更新支持单个、多个及显式全部；不能将未提供名称的非交互更新默认为更新全部。
- 参数完整时不再等待交互；无交互终端而参数不足时返回参数错误，不挂起。JSON 模式不能将菜单或路径展示混入结果输出，交互提示与进度使用诊断通道。
- 执行前展示最终路径及操作类型。更新流程明确表示将以仓库为准替换内容，授权来自用户选择的更新操作，不另要求逐文件确认。

### 首次批量安装

- 安装只处理当前选择中缺失的目标，既有目录与其内容保持不变；重新执行安装不会覆盖已经成功安装的内容。
- 先解析固定提交、下载并检查全部所选内容，成功后才开始写入目标。任一被选择内容预检失败，不留下本次安装的新目标或虚假的成功记录。
- 写入中的失败以本次安装批次为恢复边界，回滚本次新增目标及其安装记录，保留安装前已有目录。失败恢复不能删除其他进程或用户原有的内容。
- 如果清理不能完成，结果明确列出残留路径及对应状态，不声称全部恢复。安装记录保存来源、实际位置与成功提交，不能将部分写入记录为完成。

### 更新与逐目标恢复

- 更新只处理所选范围、所选标准目标中的已有安装。显式更新全部不能扫描整台机器、其他项目或未选择的目标；缺失目标不顺便补装。
- 对每个目标比较实际文件内容与本次固定的来源内容，识别新增、修改和删除。本地变更不会阻止更新，也不进行合并；最终恢复远程文件、覆盖修改并移除仓库没有的本地新增内容。
- 即使已记录提交与当前来源提交相同，也检查实际内容；存在本地差异时执行恢复，只有提交及内容均一致才报告已是最新。安装记录与临时备份应与 Skill 内容区分，不能被完整同步自身误删。
- 更新以单个实际安装目标为写入和恢复单位。替换前保留该目标写入前的内容及管理状态；内容与安装记录成功后才将该目标报告为完成。
- 一个目标写入失败时，仅恢复其写入前内容与安装记录，保留其他已成功目标，继续处理其余条目。同一 Skill 的多个不同目标分别拥有结果，不以 Skill 名称合并掉局部失败。
- 恢复不成功时保留可用于处理的原内容并报告恢复失败和路径，不能让成功摘要掩盖损坏状态。可处理的取消沿用相同恢复边界，不能把被中断的替换报告为成功。
- 自动关联后更新仍遵守相同规则；唯一匹配不代表本地内容与远程一致，成功提交只在目标同步完成后记录。来源被移除或当前不可用时明确跳过或报告对应错误，不自动重新添加来源或改用另一个同名来源。
- 汇总逐目标成功、未变化、跳过和失败，包含可识别的来源、Skill、范围、目标位置、提交和原因。存在实际失败时返回非零退出码，失败响应同时保留成功项，不伪装为整批回滚。

### 输出、配置与兼容

- 延用 JSON 成功与失败均向 stdout 输出一个独立结果、stderr 用于诊断的契约。下载进度、路径展示、授权提示和交互菜单不污染 JSON；来源、安装与更新结果均可结构化读取。
- 沿用退出码类别：0 成功，2 参数或配置错误，3 Skill 元数据或身份冲突，4 认证或权限错误，5 文件、网络及其他 I/O 失败，130 用户取消。批量部分失败必须有非零总体结果及逐项详情，不能仅依赖诊断文本。
- 来源缓存、安装记录和配置损坏时明确报告，不能自动当成首次使用而重新播种来源或接管未知目录。实现需要确保内容和管理记录一致，避免并发或中断造成错误关联；具体持久化形式不由本规格锁定。
- 本期新增能力不修改现有博客业务契约、服务地址配置或设备授权。使用说明包含来源管理、项目级与用户级、多选安装、已有状态、手动关联、覆盖更新和部分失败处理。

## Testing Decisions

- 用户已确认统一验收入口：打包并安装后的 CLI，以真实子进程调用为主，断言公开行为、输出、退出码和实际持久化结果，不以内部函数调用次数或实现文件布局证明功能。
- 优先复用现有安装测试辅助能力：当前项目已有把发行包安装到临时 prefix 并启动命令的方式，也有真实本机 HTTP 服务及故障代理的测试先例。Skill 测试沿用这一级入口，无须引入 PageHush 作为 Skill 功能的依赖。
- 在外部 GitHub 获取边界增加本机可控协议服务，提供真实元数据和归档字节，能切换默认分支、提交、无权限、限流、断连、损坏内容及多来源局部失败。CLI 的解析、下载、校验、目标写入与记录持久化使用真实实现，不把整个 Skill 服务替换为返回预设成功的 mock。
- 私有来源授权仅在第三方边界模拟 gh；隔离其配置与凭据，不读取开发者真实登录。验证公开源未登录可用、私有源复用授权、缺少工具或权限失败有诊断，以及凭据不出现在输出和持久化数据。
- 终端多选通过伪终端驱动真实安装后的命令，观察目标选择、多选、已安装禁选、部分缺失、路径展示和取消；不能只测试被注入的预选列表。非交互测试使用无终端子进程，验证参数完整不等待及参数缺失明确失败。
- 所有测试使用临时用户目录、项目目录、配置、来源缓存和安装记录；GitHub 服务仅监听本机并由测试控制。既不修改用户现有真实 Skill，也不依赖生产 GitHub 的在线状态或本人的私有权限。
- 来源验收覆盖初始三项、规范化去重、添加第四个来源后无需发版即可发现、跨项目配置共用、移除不卸载、重启不重新加入、重新添加恢复更新。验证一仓库一 Skill、name 与仓库名不同、无效入口和同名歧义。
- 列表验收同时观察总数与来源状态：暂不可用保留历史条目并标注、首次失败不报告权威零项、部分成功保留其他来源、缓存不可用于冒充最新安装或更新。
- 安装验收覆盖项目级默认与显式位置、用户级、三种标准目标、多目标去重、中文和空格路径、多个 Skill、部分已有与全部已有、手动目录保护、完整附属资源及 Git 元数据排除。确保脚本与依赖安装均未执行。
- 使用可变来源验证快照固定：在下载或多目标写入期间推进默认分支，确认同一次操作始终使用同一提交，下次调用才取得后续提交。
- 安装失败测试在真实文件系统边界制造可观察的下载、验证和写入失败，检查本次新增内容及记录被回滚、原有目录字节未变；制造清理失败后检查返回的残留路径。不以“抛出异常”代替恢复结果断言。
- 自动关联验收覆盖唯一匹配、无匹配、多个匹配、不可解析的手动目录及来源移除；检查来源身份与实际位置记录，不把关联误写为已完成同步。
- 更新验收覆盖单个、多个、显式全部和交互多选，确认范围仅限所选位置、缺失目标不补装、本地修改被覆盖、删除被恢复、新增文件被移除。同提交但本地不同仍恢复，内容与提交一致才报告最新。
- 更新失败测试让第一个目标完成、第二个目标在实际写入中失败、第三个仍可继续，核对第一个保留新内容、第二个及其记录恢复原状、第三个完成；核对总体非零及完整逐项结果。另覆盖恢复失败的实际报告与可处理取消的恢复边界。
- 通过畸形名称、越界归档和链接目标测试，证明获取或替换不会写到所选 Skill 安装之外；对相邻目录设置哨兵内容并核对字节不变。
- 同一生命周期从安装包入口贯通来源添加与刷新、列表、多选安装、手动关联、覆盖更新、部分失败、来源移除及重新登记。完成现有博客相关回归与类型、格式、构建检查，记录 macOS 实际安装包验收结果；未运行的场景不标为通过。

## Out of Scope

- 博客远程文章编辑及其他博客能力扩展。
- 多 Skill 集合仓库、嵌套 Skill 自动发现、扫描整个 GitHub 账号或接入其他托管平台。
- 独立 Skill Registry、manifest 发布协议、SemVer 选择、任意分支选择、指定旧提交回退和 GitHub release 管理。
- Skill 自己实现更新、保留或合并本地修改、逐文件选择覆盖、把更新变成双向同步。
- Skill 卸载、定时更新、后台监听或无人确认地周期同步。
- 任意自定义安装目标、遍历整台机器寻找安装，或更新时补装缺失目标。
- 安装或运行 Skill 的依赖、执行来源脚本和钩子、配置 Skill 运行密钥、保证每个 Skill 的业务运行环境已经满足。
- 替用户修改 GitHub 仓库可见性、管理 GitHub 账号权限或新增保存令牌的授权系统。
- Linux、Windows 完整验收、公开 npm 发布、AI 对话产品接入及 MCP 服务。
- 为本规格执行真实 Skill 安装或覆盖更新；实际实现与交付验收属于后续任务。

### 2026-10-24 补充确认：安装状态、声明版本与自动更新位置

用户明确版本读取根 `SKILL.md` 的 `version`，并确认选择一个 Skill 后更新其所有已记录安装位置。本节优先于前文关于再次选择更新范围、仅处理当前项目所选目标及无需声明版本的早期约定。

- 普通列表标题和表头居中。完整说明、来源可用性状态继续保留在 JSON 中，声明版本和各目标安装版本作为新增数据。
- 无参数交互更新先检查最新来源提交和实际安装文件，仅将有变化的受管 Skill 列入菜单。提交与内容都相同时提示“无可用更新，Skill 均为最新版”。本地修改仍需同步；来源错误、歧义或名称变化单独报告，不能误报为最新版。
- 选择 Skill 后立即更新其所有已记录安装位置，包括其他项目，不再询问用户目录、项目目录或目标工具。仅按记录访问其他项目，不扫描其他项目寻找未记录目录；手动安装的发现仍限当前项目和当前用户的三个标准目标。
- 名称和 `--all` 调用默认使用相同的自动位置规则；显式 `--scope`、`--target` 或 `--project-path` 仍可收窄范围。非交互调用未提供名称或 `--all` 时仍拒绝执行。
- 更新结果表格仅保留 Skill、状态、版本。成功显示“已更新”，失败显示“更新失败”，版本显示本次获取的最新声明版本；未取得最新元数据时显示“未获取”。失败原因放在表格下方。
- `version` 仅用于展示，内容仍来自固定的默认分支最新提交；不增加历史版本选择或按 SemVer 排序更新。原有首次安装整批回滚、更新逐目标恢复、成功项保留及 JSON 输出通道契约继续有效。
