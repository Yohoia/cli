# Skill 管理任务计划

依据：[正式规格](spec.md)。用户已确认九项拆分与依赖，独立任务单已发布到 issues 目录，状态为 ready-for-agent。随后按用户已调用的 implement 完成九项实现与验收；详见[验收记录](acceptance.md)。

## 拆分原则

- 每项从安装后的 CLI 入口走到可观察结果，包含相应参数、文本与 JSON、持久化行为及隔离测试，不按模块或技术层分别建任务。
- 当前 CLI 已有命令、输出和安装包测试入口，不需要单独做宽泛重构。为新增结果类型和命令注册所需的最小调整随 01 完成，不预先扩大博客模块改动。
- 02 与 03 可在 01 完成后分别推进；05 与 06 可在 04 完成后分别推进。下面只列直接依赖，不重复传递依赖。

## 依赖说明

- 01 是首条完整读取路径，同时建立来源身份与用户配置；它不需要安装能力即可独立演示。
- 02 只补充来源访问及不可用状态，03 只以公开来源贯通最小安装，两者不互相阻塞。03 不宣称已经支持最终的私有来源安装与多目标批次语义。
- 04 的私有来源安装需要 02 的授权获取能力，批量文件写入和记录需要 03 的单安装行为，因此直接依赖二者。
- 05 依赖 04 的目标状态和完整安装行为，不另造交互专用安装实现；真实终端选择是该项的直接用户行为，不是单独的 UI 技术层任务。
- 06 依赖 04 的安装记录、多目标定位和获取能力，但不依赖 05 的菜单；非交互覆盖更新可以先独立验收。
- 07 在 06 的完整更新行为上增加手动安装纳管，不能仅创建来源关联记录而没有可用更新链路。
- 08 同时依赖 05 已验证的终端体验和 07 完整更新能力，避免更新菜单先于真实操作完成。
- 09 的唯一直接依赖是 08，其传递依赖覆盖全部任务。09 负责最终连贯交付，不承接前面本该完成的失败恢复、权限或菜单验证。

## 各项共有的验收约束

- 使用打包安装后的 CLI 和真实临时文件系统。GitHub 使用本机可控协议服务，gh 只在第三方授权边界模拟；真实终端菜单使用伪终端操作，不注入预设选择代替交互证明。
- 来源、配置、缓存、安装记录、项目和用户目录均隔离，不读取真实 GitHub 凭据，也不改动现有真实 Skill。不依赖 GitHub 在线状态，不运行来源脚本或安装依赖。
- 每项从引入相应能力时覆盖其 JSON stdout、诊断 stderr 和退出码契约；参数完整不等待交互，非交互参数不足明确失败。
- 按固定提交获取并保留完整资源。单次操作中来源推进时不能混用提交；路径、归档和链接不得使写入或恢复逃逸所选 Skill 安装。
- 首次批量安装使用整批回滚，更新使用按目标恢复，不能因内部复用合并语义。取消、清理或恢复失败时明确报告实际状态及相关路径。

## 发布任务单时展开的关键验收

1. **01：来源与列表。** 仓库标识和链接规范化去重；初始三个与新增第四个来源；name 不同于仓库名；单根入口、无效元数据与安全目录名；已知数量与来源状态；配置损坏明确报错而非重新初始化。移除来源不接触已有文件，重新启动不重加。
2. **02：授权与失败。** 无 gh 的公开访问、私有授权获取、缺少工具/未登录/无权限、限流和断连；保留成功缓存并标记不可用，首次失败不显示权威零项；局部可用性及同名来源显示；令牌不落盘、不泄漏、不发往无关地址。安装和更新稍后复用该访问边界，不另实现凭据系统。
3. **03：单个安装。** 真实归档、脚本/引用/图片等完整资源、无 Git 元数据、无脚本执行；默认分支不固定为 main，提交固定；存在目录及不可解析占位均不覆盖，成功记录来源/提交/实际位置；下载、检查和写入失败不误记完成；畸形名称、越界归档及来源链接不写相邻目录。
4. **04：多目标批次。** 项目默认、其他项目路径、用户范围、三标准目标、同物理目录去重、中文与空格路径；私有与公开混合、多 Skill、部分已有与全部已有；全部下载校验完成后才写目标，一处失败撤销本批新增及记录，原目录与其他进程已存在内容保留；清理失败报告残留；来源中途推进多目标仍一致，目标边界及并发记录一致性得到验证。
5. **05：终端安装。** 真实按键选择多个 Skill 和目标；已安装标记不等于预勾选、全已有禁选、部分已有只补缺失、不可用项禁选；完整路径展示；取消不报告安装成功；无终端参数不足不挂起；与非交互安装使用同一能力。
6. **06：记录安装更新。** 单个、多个和显式全部；只查所选范围，不补装缺失目标；覆盖修改/恢复删除/移除本地新增，同提交有差异仍恢复；提交及内容一致才报告最新。第一个目标成功、第二个实际写入失败、第三个仍继续；失败项内容和记录恢复，成功项保留；恢复失败保留可处理原内容并报告路径，可处理取消按同一恢复边界执行；部分失败 JSON 包含成功项和非零总体结果。
7. **07：手动纳管。** 唯一 name 匹配、无匹配、歧义、损坏入口、手动安装位置与标准名称不同的实际位置记录；来源关联与更新成功提交区分；失败不冒记新提交。移除来源暂停且不卸载、不自动重新登记，重新添加恢复；已记录来源身份不被同名其他仓库替换，来源名称改变时不静默重命名安装。
8. **08：终端更新。** 记录与手动安装混合展示，更新多选、显式全部、逐目标状态及仓库覆盖说明；同名来源和无法关联原因明确；失败后其余项继续及结果汇总；菜单、进度、路径和授权提示不污染 JSON；可处理取消不将中断操作报为完成。
9. **09：完整交付。** 安装包在隔离环境跑通来源添加/刷新、安装及更新菜单、手动关联、同提交修复本地变化、部分失败、移除/恢复来源；帮助说明覆盖两个恢复边界、覆盖本地文件规则及实际运行依赖不由安装器处理。完成类型、格式、构建与既有博客回归，记录实际运行证据，不用真实 Skill 执行覆盖验证。
