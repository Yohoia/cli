# Skill 更新提示

用户要求已安装 Skill 发布新版本时显示标识，借鉴本机 Mole 的更新提示。沿用现有 Skill 页面、文本列表与按 U 更新流程。

## 行为

- 进入 Skill 页面、运行 `yoho skill list` 或按 R 刷新时，复用本次来源刷新结果，比较每个已有安装位置。
- 本地和来源均声明有效语义版本时比较版本优先级，兼容 `v` 前缀、数字预发布标识与构建元数据。仅较新的来源版本触发提示，相同版本、构建元数据变化和较旧版本不提示升级。
- 任一侧未声明版本时，仅有明确来源记录及安装提交的目标可以比较提交；不同提交显示来源有更新。没有足够信息的手动安装、来源不可用、来源身份变化、同名来源歧义及不安全目标，标记更新未确认。
- 检测只读取安装文件及已有记录，不修改 Skill、不建立新的来源关联。来源目录缓存仍按既有刷新机制保存。
- JSON 中安装目标增加 `updateStatus: available | current | unknown`，有更新时附带 `updateReason: version | commit`。缺失目标不声称有更新。`current` 仅表示来源版本或提交未发现升级，不保证本地内容没有修改；实际更新仍比较完整文件。
- 列表用黄色 `↑ 有更新`，已安装版本保留并显示 `当前版本 → 来源版本`。列表上方汇总有更新的 Skill 数量，同一 Skill 多个位置仅计数一次。Mole 风格提示中 `U Update` 使用绿色，焦点青色、多选绿色保持原规则。窄屏优先保留更新标识，完整版本及逐目标信息可打开详情查看。
- `U` 仍作用于当前焦点或勾选的 Skill，确认页展示版本及覆盖说明，默认取消。更新成功后重新读取列表，提示随实际安装版本消失；失败安装继续提示。普通命令列出 `yoho skill update` 操作提示。
- 不增加后台轮询、启动首页网络请求或自动安装。更新仍取来源默认分支的当前提交，不引入历史版本选择或回滚。

## 参考与验证

参考本机 Mole 1.64.0 的 `libexec/mole` 中 `_main_menu_update_notice`：独立更新消息、绿色更新操作；保持 Yoho 现有菜单与工具栏。

验收覆盖语义版本、预发布顺序、混合安装版本、范围过滤、无版本提交、缓存失败、手动安装歧义、更新后消除提示，以及 120/60 列真实 PTY 的提示、确认与更新流程。结构检查和完整回归按项目要求执行。
